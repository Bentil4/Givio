## Deferred from: Wave 3 parallel implementation of 6-5, 7-1, 8-3, the AD-2 tenant-read amendment and the route-diagram CI fix (2026-09-30)

- **Tenant-read recompute can exceed the synchronous 30-second limit** — AD-2x rewrites every Event and Donation row of a tenant, one `updateRow` at a time, on each organizer add/revoke and tenant approve/suspend/reject. The app calls the Function synchronously, and Appwrite caps synchronous executions at 30 s regardless of the Function timeout (raised from 15 s to 30 s live on 2026-09-30). Large tenants need the recompute moved to an asynchronous execution or a queued job, with the caller polling for completion. `functions/set-role-and-permissions/src/tenant-grants.js`.
- **Appwrite's 100-entry row permission cap** — beyond about 97 readers on one Event, organizer-tier grants are dropped first and the Event is reported in `truncatedEventIds`. The cap comes from Appwrite's source (`APP_LIMIT_ARRAY_PARAM_SIZE`), not its docs; confirm on the live project.
- **Run the tenant-read backfill after AD-2x deploys** — `{"action":"recomputeTenantReadGrants"}` (Admin, no `tenantId` = all tenants). A no-op today (no tenant-owned Events), but required once any exist from before the amendment.
- **Revoked co-Organizers keep their sessions (7.1 → 7.3)** — their Membership is refused everywhere, but the Account isn't blocked and sessions aren't revoked, unlike an Admin-deactivated user.
- **A failed team revoke can't be retried from the screen (7.1)** — the row disappears (revoked Memberships aren't listed) even when a post-revoke step returned 502; retry is only possible by a direct call.
- **No email invite for team members (6.3/7.1)** — the generated password is shown once in the UI.
- **No Admin viewer for support requests (8.3)** — rows are stored and Admin-readable but nothing lists them; it also needs an Admin action to close a request, since rows are read-only for Admin.
- **Nothing links to `/company/dispute` (8.3 → 8.1)** — a locked-out Organizer needs a link from the login page and from 8.1's suspension messaging.
- **Dispute rate limit trade-off (8.3)** — a flood can fill the global 60-per-hour cap and block genuine disputes for up to an hour; constants are exported for tuning.
- **No audit entries for tenant verify/approve/reject (6.5)** — `audit_logs.entityType` has no tenant type.
- **Signup collects no applicant phone number (6.4/6.5)** — Admin must find it from the document or by email to make the verification call.
- **Approval document link may 401 cross-domain (6.5)** — `getFileView` relies on the Admin's Appwrite session cookie reaching the Appwrite endpoint; verify live with third-party cookies blocked.
- **Sidebar highlights "Dashboard" on every `/company` page** — the shared sidebar's `routerLinkActive` isn't exact-match; the admin layout behaves the same.
- **Route diagram auto-PR needs repo settings** — enable "Allow GitHub Actions to create and approve pull requests", and preferably add a `ROUTE_DIAGRAM_PR_TOKEN` fine-grained PAT (Contents + Pull requests read/write, ideally a machine account) so CI Gate runs on the sync PR. The GITHUB_TOKEN fallback (dispatching CI on the sync branch) is unverified against branch protection.
